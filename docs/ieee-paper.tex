\begin{abstract}
LogiFlow is a real-time microservices platform for fleet routing where operational continuity and data integrity depend on trustworthy service interactions. This paper presents a complete DevSecOps security monitoring architecture that compares a vulnerable baseline against a hardened production-oriented implementation. We identify attack surfaces in API, WebSocket, webhook, container runtime, and CI/CD supply-chain paths, and prioritize threats through STRIDE and OWASP Top 10 (2021). The architecture integrates shift-left controls (CodeQL, Semgrep, npm audit, GitLeaks, Trivy, OWASP ZAP) with shift-right telemetry (Falco, Prometheus, Loki, Grafana) and distributed tracing (OpenTelemetry and Tempo). Evaluation using TC-01 to TC-10 demonstrates mitigation of high-risk scenarios such as unauthorized socket access, forged webhook injection, and request-flood abuse, while also improving triage speed through metric-log-trace correlation. The resulting artifacts form a reusable blueprint for academic and industry teams implementing continuous security in distributed systems.
\end{abstract}

\section{Introduction}
Microservices increase agility and horizontal scalability, but they also expand trust boundaries and failure modes \cite{newman2015,dragoni2017}. In transportation and logistics platforms, a single compromised component can cascade into routing disruption, data exposure, or dispatch paralysis.

This work addresses the SPTI objective of security-by-design with measurable evidence, implementing and validating a full DevSecOps security layer over LogiFlow. The main contributions are:
\begin{enumerate}
\item A reproducible vulnerable-to-hardened architecture comparison with explicit vulnerability-to-control traceability.
\item An integrated CI/CD security pipeline with SAST, SCA, secrets detection, container scanning, and DAST.
\item A continuous monitoring and triage architecture that correlates metrics, logs, runtime anomalies, and traces.
\end{enumerate}

\section{Background}
\subsection{Security and Governance Foundations}
OWASP Top 10 (2021) is used as the vulnerability taxonomy \cite{owasp2021}. STRIDE threat modeling provides a structured lens over spoofing, tampering, repudiation, information disclosure, denial of service, and elevation of privilege \cite{shostack2014}.

NIST CSF 2.0 and SSDF align governance with engineering execution, requiring traceable controls and repeatable verification \cite{nistcsf,devsecopsnist}. Additional control baselines and weakness references are mapped through NIST SP 800-53 and CWE knowledge bases \cite{nist80053,cwe}.

\subsection{Tooling and Observability Ecosystem}
The implementation combines static and dynamic controls in CI (CodeQL, Semgrep, Trivy, ZAP) \cite{codeql,semgrep,trivy,zap} and continuous runtime telemetry through Falco, Prometheus, Loki, Grafana, OpenTelemetry, and Tempo \cite{falco,prometheus,loki,grafana,opentelemetry,tempo}.

\section{LogiFlow System Description}
\subsection{Service Topology and Technology Stack}
LogiFlow includes gateway, realtime, optimizer, automation, Redis, and PostgreSQL services. Authentication is JWT-based \cite{jwtRFC7519}; low-latency updates use Socket.IO \cite{socketio}; data and event storage rely on PostgreSQL and Redis \cite{postgresql,redis}.

\subsection{Implemented Gates and Recent Reliability Fixes}
\begin{itemize}
\item \textbf{SAST}: CodeQL and Semgrep for JavaScript/TypeScript.
\item \textbf{SCA}: per-service dependency audit artifacts.
\item \textbf{Secrets}: GitLeaks baseline in CI.
\item \textbf{Container Security}: Trivy over gateway Docker context. A non-root user was added to satisfy DS-0002.
\item \textbf{DAST}: ZAP baseline and parser-based gating against gateway target URL.
\item \textbf{CI Hardening}: automatic creation of external Docker network before DAST compose startup.
\end{itemize}

\subsection{Observed Security Posture Improvements}
Compared to the vulnerable baseline, the hardened implementation provided:
\begin{itemize}
\item Stronger prevention against external exploit paths (API, socket, webhook).
\item Earlier defect detection in CI through layered static and dynamic gates.
\item Better incident forensics through correlated metrics, logs, runtime events, and traces.
\item Improved pipeline reliability after resolving Trivy non-root policy and DAST network bootstrap issues.
\end{itemize}

\subsection{Limitations}
The current implementation emphasizes practical reproducibility over enterprise-scale hardening. Remaining gaps include managed secret rotation, formal SOAR playbooks, and long-horizon benchmarking for MTTD/MTTR under sustained attack simulation.

\section{Conclusions and Future Work}
This paper presented a complete, evidence-driven DevSecOps monitoring architecture for LogiFlow. The transition from vulnerable baseline to hardened implementation reduced exploitable paths and improved operational visibility for security response.

Future work includes: (i) vault-backed and automated secret rotation, (ii) SOAR-assisted response automation for Falco and Prometheus alerts, (iii) policy-as-code maturity for supply-chain governance, and (iv) quantitative longitudinal benchmarking of detection and response performance.
